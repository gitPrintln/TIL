# AI Identity & Delegation Security

AI 에이전트가 사용자를 대신해 인증하고 신원 및 권한(위임서)을 행사하는 환경에서는 **신원 증명(Identity), 권한 범위 통제(Authorization), 위변조 방지(Integrity)**가 핵심 보안 요소가 됩니다.

## 1. 3대 핵심 개념과 보안 역할

| 영역 | 핵심 기술 / 표준 개념 | 보안 관점의 역할 |
| :--- | :--- | :--- |
| **AI 인증**<br>(AI Authentication) | 에이전트 신원(Agent ID), mTLS, OAuth 2.0 / OIDC 확장, 하드웨어 기반 키(TPM/TEE) | 요청을 보낸 주체가 **인가된 정상 AI 에이전트인지** 확인하고, 봇 위장·탈취 및 딥페이크/프롬프트 인젝션 기반 사칭을 차단합니다. |
| **디지털 신분증**<br>(Digital ID / VC) | **DID** (분산신원증명), **VC** (검증 가능한 자격증명), **mDL** (모바일 운전면허증), **ZKP** (영지식 증명) | 중앙 서버 의존도를 낮추면서 신원 정보의 **진위와 무결성을 암호학적으로 검증**하고, 필요한 최소 정보만 선택적으로 공개(Selective Disclosure)합니다. |
| **전자 위임서**<br>(Delegation / Capability) | **RAR** (Rich Authorization Requests), **GNAP**, 위임 토큰(Delegation Token), **MAC/전자서명** | 사용자가 AI에게 **'무엇을, 언제까지, 어떤 한도 내에서'** 대리 수행할 수 있는지 명시적으로 권한을 위임하고 부인방지를 보장합니다. |

## 2. 주요 보안 위협 및 대응 방안

### ① 신원 사칭 및 AI 에이전트 탈취 (Spoofing & Hijacking)
* **위협**: 공격자가 정상 AI 에이전트로 위장하거나, 탈취된 API 키·세션 토큰을 악용해 사용자 권한으로 시스템에 접근합니다.
* **대응**:
  * 에이전트별 고유 암호화 키 쌍 발급 및 단기 수명(Short-lived) 토큰 사용
  * 토큰 탈취 후 재사용을 막기 위한 **발신자 제약 토큰(Sender-Constrained Token, 예: DPoP, mTLS)** 적용

### ② 과도한 권한 위임 및 권한 상승 (Over-Privilege & Confused Deputy)
* **위협**: 위임서의 권한 범위가 모호할 경우, AI가 의도치 않게 결제·계약·개인정보 조회 등 민감한 작업을 초과 수행하거나 프롬프트 인젝션에 속아 악의적 명령을 실행합니다.
* **대응**:
  * **최소 권한 원칙(Least Privilege)** 기반의 세분화된 위임서 발급 (행위, 금액 한도, 대상 서비스, 만료 시간 명시)
  * 고위험 작업 실행 시 사용자의 생체·패스키 재확인을 요구하는 **Step-up 인증(Human-in-the-Loop)** 결합

### ③ 위임서·신분증 위변조 및 재전송 공격 (Tampering & Replay)
* **위협**: 네트워크상에서 위임서나 신원 증명 데이터를 가로채 내용을 수정하거나, 이미 만료·사용된 위임서를 반복 제출합니다.
* **대응**:
  * 발급자(사용자/인증기관)의 **전자서명(Digital Signature)**을 통한 무결성 및 부인방지 확보
  * 일회성 난수(**Nonce**), 타임스탬프, 실시간 폐기 상태 검증(Status List / Revocation) 적용

### ④ 신원 정보 과다 노출 및 추적 (Privacy Leakage)
* **위협**: 신분증 제시 과정에서 불필요한 개인정보(주민등록번호, 주소 등)까지 AI 서비스나 제3자에게 노출되어 프로파일링·유출 위험이 커집니다.
* **대응**:
  * **선택적 공개(Selective Disclosure)** 및 **영지식 증명(ZKP)**을 통해 원본 신분증 전체가 아닌 *"성인임"*, *"인가된 대리인임"* 같은 검증 결과만 전달

## 3. 전체 인증·위임 검증 흐름 요약

1. **신원 확인 (Digital ID)**: 사용자가 디지털 신분증(VC/DID)과 생체·패스키 인증으로 본인임을 증명합니다.
2. **위임서 발급 (Delegation)**: 사용자가 AI 에이전트의 공개키와 작업 범위·유효기간을 묶어 전자서명된 위임 토큰을 발급합니다.
3. **에이전트 요청 및 검증 (AI Auth)**: AI 에이전트가 대상 서비스에 요청할 때 **자신의 서명(에이전트 인증)**과 **사용자의 위임서(권한 증명)**를 함께 제출합니다.
4. **정책 집행 (Policy Enforcement)**: 서비스는 발급자 서명, 위임 범위, 폐기 여부를 검증한 뒤 허용된 범위 내에서만 작업을 승인합니다.

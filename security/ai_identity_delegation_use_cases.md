# AI Identity & Delegation Use Cases

AI 인증, 디지털 신분증(DID/mDL), 전자 위임서가 실제 서비스 환경에서 어떻게 결합되어 보안을 유지하는지 보여주는 4가지 핵심 시나리오입니다.

---

### 1. 쇼핑 및 결제 대행 시나리오 (금융·커머스)
* **상황**: 사용자가 개인 AI 비서에게 *"이번 주 안에 10만 원 이하로 무선 이어폰을 주문해 줘"*라고 지시함.
* **보안 적용 흐름**:
  1. **AI 인증**: 쇼핑몰 서버는 요청 주체가 인간의 계정을 탈취한 봇이 아니라, 사용자가 정식 인가한 **AI 에이전트(Workload Identity)**임을 상호 인증(mTLS 등)으로 확인합니다.
  2. **전자 위임서**: 사용자의 개인키로 서명된 위임 토큰(RAR 기반)에 **`금액 상한: 100,000원`**, **`품목: 전자기기`**, **`유효기간: 7일`**이라는 최소 권한 조건이 명시됩니다.
  3. **방어 효과**: 만약 프롬프트 인젝션 공격으로 AI가 200만 원짜리 노트북 결제를 시도하더라도, 결제 게이트웨이가 전자 위임서의 조건(상한선 초과)을 검증하여 거래를 즉시 차단합니다.

### 2. 기업 재무·법무 문서 열람 및 전자계약 (B2B 업무)
* **상황**: 회계 담당 AI 에이전트가 외부 세무법인 시스템에 접속해 연말정산 자료를 제출하고 확인서를 발급받음.
* **보안 적용 흐름**:
  1. **디지털 신분증(VC)**: 회사가 발급한 **법인 소속 증명서(Verifiable Credential)**를 통해 해당 AI가 특정 기업의 정식 업무 대리인임을 증명합니다.
  2. **영지식 증명(ZKP)**: 불필요한 임직원 전체 급여 명세나 기밀을 노출하지 않고, *"세무 신고 권한이 있는 유효한 법인 소속임"*만 선택적으로 공개(Selective Disclosure)합니다.
  3. **전자 위임서 및 감사 추적**: 법무·재무 책임자가 발급한 전자 위임서 범위 내에서만 서명이 실행되며, 모든 행위는 인간 위임자와 AI 식별자가 함께 기록된 감사 로그로 남아 **부인 방지**를 보장합니다.

### 3. 의료 제증명 발급 및 보험 청구 자동화 (헬스케어·행정)
* **상황**: 환자가 모바일 건강 AI 에이전트에게 *"어제 진료받은 내역으로 실손보험 청구를 진행해 줘"*라고 요청함.
* **보안 적용 흐름**:
  1. **디지털 신분증(mDL/모바일 신분증)**: 병원 및 보험사 앱은 사용자의 모바일 신분증 기반 본인인증과 생체인증(패스키)을 통해 최초 위임 동의를 확인합니다.
  2. **선택적 정보 공개**: AI는 전체 진료 기록 중 민감한 병력을 제외한 **'진료 일자·수납 금액' 항목만** 암호화 서명된 형태로 추출해 보험사에 제출합니다.
  3. **즉시 철회(Revocation)**: 청구가 완료되는 즉시 위임 토큰이 만료되거나 상태 목록(Status List)에서 폐기되어, 이후 AI가 의료 기록에 재접근하는 것을 원천 차단합니다.

### 4. 개발 및 클라우드 인프라 배포 (DevSecOps)
* **상황**: 배포 담당 AI 에이전트가 코드 리뷰를 마친 뒤 운영 서버(Production)에 패치를 배포함.
* **보안 적용 흐름**:
  1. **단기 수명 자격증명(Ephemeral Credentials)**: AI에 영구적인 API 키나 관리자 비밀번호를 부여하지 않고, 배포 작업 순간에만 유효한 단기 위임 토큰을 발급합니다.
  2. **Step-up 인증(단계별 추가 인증)**: 일반 스테이징 환경 배포는 AI 단독 위임 권한으로 처리하되, 핵심 DB 스키마 변경이나 운영 서버 반영 직전에는 **인간 관리자의 모바일 생체인증 승인(Human-in-the-Loop)**을 추가로 요구합니다.

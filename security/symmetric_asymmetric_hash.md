# 암호 기법 분류 핵심 정리

암호 기법은 크게 **키 사용 방식(대칭키·비대칭키)**, 그리고 **일방향 무결성 검증(해시 함수)** 관점으로 나누어 이해할 수 있습니다.

## 1. 대칭키 암호 vs. 비대칭키(공개키) 암호 (키 사용 방식)

| 구분 | 대칭키 암호 (Symmetric-Key) | 비대칭키 / 공개키 암호 (Asymmetric / Public-Key) | 
| :--- | :--- | :--- | 
| **키 구조** | 암호화와 복호화에 **동일한 비밀키(1개)** 사용 | **공개키(Public Key)**와 **개인키(Private Key)** 한 쌍 사용 | 
| **처리 속도** | 연산 구조가 단순해 **매우 빠름** (대용량 데이터에 적합) | 복잡한 수학적 연산(소인수분해, 이산대수, 타원곡선 등) 기반으로 **상대적으로 느림** | 
| **키 배송 문제** | 통신 전 비밀키를 안전하게 공유·전달하는 문제 발생 | 공개키는 외부에 공개해도 되므로 **키 교환이 용이**함 | 
| **대표 예시** | AES, ChaCha20, ARIA, SEED | RSA, ECC(ECDSA, ECDH), Ed25519 | 
| **주요 용도** | 대용량 파일·트래픽 본문 암호화 | 세션 키 교환, 전자서명(인증·부인방지), 소규모 데이터 암호화 | 

> **참고**: 실무(예: TLS/HTTPS)에서는 두 방식의 장점만 결합한 **하이브리드 암호 체계**를 사용합니다. 즉, **비대칭키**로 안전하게 세션 키를 교환한 뒤, 실제 대용량 데이터 통신은 빠른 **대칭키**로 암호화합니다.

## 2. 암호화 해시 함수 (Cryptographic Hash Function — 일방향 무결성 검증)

| 구분 | 암호화 해시 함수 (Hash Function) | 
| :--- | :--- | 
| **핵심 원리** | 임의 길이의 입력 데이터를 **고정 길이의 해시값(Digest)**으로 매핑하는 **일방향(단방향) 함수** | 
| **복호화 여부** | **불가능** (암호화·복호화가 목적이 아니라 데이터 지문 생성 및 검증이 목적) | 
| **필수 보안 성질** | • **역상 저항성**: 해시값으로 원래 입력값을 유추하기 어려움<br>• **제2역상 저항성**: 특정 입력과 같은 해시값을 내는 다른 입력을 찾기 어려움<br>• **충돌 저항성**: 해시값이 같은 서로 다른 두 입력 쌍을 찾기 어려움 | 
| **대표 예시** | SHA-256, SHA-3, BLAKE2 / BLAKE3 (MD5, SHA-1은 충돌 취약점으로 보안 용도 폐기) | 
| **주요 용도** | 파일·메시지 **무결성 검증**, 비밀번호 저장(솔트+키 스트레칭 결합: Argon2, bcrypt 등), 전자서명 요약 |
